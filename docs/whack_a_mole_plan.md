# 投影打地鼠：新项目准备

整理日期：2026-10-07。

项目名：MoleGame，目录：`D:\project\MoleGame`。
基础阶段提供单坑鼠标预览和独立相机手检测预览；已复用手模型与推理代码。
正式相机地鼠判定、标定和实验记录待接入。现有音游保留为实现参考和实验记录来源。

## 研究任务

先做一个坑的投影打地鼠任务：地鼠随机出现，参与者看见后从坑外挥手进入击打区域。
逐步缩短地鼠的显示时间，观察实际有效动作和系统判定之间的差异。

研究问题：相比系统内部计时，相机在同一帧中观察手和实际投影地鼠，
能否减少由显示时序错位引起的漏判，并改善判定公平感、响应感和游玩体验？

相机方案的优势是待验证的假设；遮挡、漏识别和取帧间隔仍可能造成误判或无法判定。

| 对照方法 | 地鼠状态的来源 |
| --- | --- |
| 内部计时 | 程序记录的出现、消失时刻 |
| 相机观测 | 手与地鼠所在的同一张原始相机图像 |

两种方法共用手部输入、击打区域、动作规则、显示时长、随机出没分布和反馈形式。
内部计时是否增加固定延迟补偿，正式实验前与教授确认；未经补偿的对照结果不能直接说明优于所有内部计时方法。

## 最小原型

- 一个固定坑，一只手，一个位置固定、颜色明显的地鼠图案。
- 出现前手在坑外；随机等待时间避免按固定节奏提前挥手。
- 显示时长可调；200 ms 是候选值，不是已确认的实验参数。
- 初步动作规则：手部检测中心从区域外第一次进入固定击打区域，算一次击打。
- 进入区域那一刻地鼠实际可见，算有效动作；不要求手完全覆盖地鼠。
- 每个地鼠最多命中一次；下一次动作前手须离开击打区域。
- 这是二维区域击打任务，单靠现有图像不能确认实际敲击投影面。

先用较长窗口确认规则和识别可靠，再根据实际“看见到进入区域”的时间选择短窗口。
显示图案和两种判定共用同一套区域，避免识别框随遮挡缩小后改变命中范围。

## 时间与遮挡

若输出延迟近似固定为 L，内部窗口 [0, W] 对应实际投影窗口 [L, W + L]。
实际显示时长仍为 W，未经补偿的内部窗口会提前结束。
例如 W=200 ms、L=40 ms 时，内部窗口为 0～200 ms，实际窗口为 40～240 ms；
发生在 220 ms 的击打可能仍然有效，但内部计时已经结束。

40 ms 投影延迟、45～55 ms 总延迟、150 ms 人的反应时间，目前都不是本任务的实测结果。
开始动作的反应时间与完成击打的时间分开记录，不用通用反应时间直接确定显示时长。

两种方法按动作所在图像帧的时间判定，不按游戏收到结果的时间判定。
现有 capturedAt 是图像转换后的主机时间，不是相机曝光时间；测量时须保留这个限制。
帧处理完成与可见反馈出现也不是同一个时刻。

检测不到地鼠，可能是真消失，也可能被手遮住。第一版先检查部分遮挡下是否仍能识别颜色；
必要时让地鼠外围保留与它同步显示、手不易遮住的颜色区域，两种方法使用相同画面。
完全遮挡或时间边界无法确认时，记录“无法判定”，不能直接算地鼠消失，
也不能随意延长状态保持时间以获得命中。

## 评价与记录

- 玩家表现：实际可见期间的击打成功率，以及看见到开始动作、进入区域的时间。
- 判定表现：对照独立录像标注，统计正确判定、误判、漏判和无法判定。
- 主观体验：是否感觉打中了却没算、反馈是否及时、判定是否容易理解、整体是否容易操作。

相机方法自己的输出不能作为两种方法的正确答案。用包含实际投影面和手的录像进行核对，
时间边界无法分辨的试次保留并报告数量。电脑录屏不能单独证明实际显示时刻。

每次运行先保存一份参数和一份事件 CSV：试次、模式、显示时长、随机种子、
内部出现/消失时刻、图像帧编号/时间、手进入区域时刻、接收/判定时间、结果及不确定原因。
实际投影出现/消失和可见反馈时刻，由图像观测或录像核对填写，并明确来源。
同一批参与者体验两种方法，平衡顺序，避免把练习效果当作方法差异。

## 下一步顺序

1. 在独立的 MoleGame 目录使用已有 C++、OpenCV、pylon、TensorRT 环境。
2. 实机验证相机预览与单手检测；模型静态图片检查不能代替真实手部验证。
3. 加入一个坑和固定图案，验证随机显示与同帧图像中的实际显示状态。
4. 检查手遮挡地鼠时能否获得可靠状态，再接入共用动作规则的两种判定。
5. 保存事件记录，拍摄实际投影画面；根据试玩选择显示时长，再准备主观评价。

第一版保持紧凑。出现真实需要后再增加模块或实验条件。
