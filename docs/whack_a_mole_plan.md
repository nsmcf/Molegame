## 研究任务

先做一个坑的投影打地鼠任务：地鼠随机出现，参与者看见后从坑外挥手进入击打区域。
逐步缩短地鼠的显示时间，观察实际有效动作和系统判定之间的差异。

研究问题：相比系统内部计时，相机在同一帧中观察手和实际投影地鼠，
能否减少由显示时序错位引起的漏判，并改善判定公平感、响应感和游玩体验？

相机方案的优势是待验证的假设；遮挡、漏识别和取帧间隔仍可能造成误判或无法判定。
项目目标是通过两种方法的对照，验证相机观测在短显示时间下能否改善玩家成绩，
并减少实际有效动作被漏判的情况；结论以实验结果为依据。

| 对照方法 | 地鼠状态的来源 |
| --- | --- |
| 内部计时 | 程序记录的出现、消失时刻 |
| 相机观测 | 手与地鼠所在的同一张原始相机图像 |

两种方法共用手部输入、击打区域、动作规则、显示时长、随机出没分布和反馈形式。
内部计时是否增加固定延迟补偿，正式实验前与教授确认；未经补偿的对照结果不能直接说明优于所有内部计时方法。

## 最小原型

- 一个固定坑，一只手，一个位置固定、颜色明显的地鼠图案。
- 2026-10-25 实机发现带五官地鼠被 YOLO 误检为手，导致地鼠区域被遮挡排除；
  曾用无五官黄色方块（target_style: square）验证，之后按使用要求恢复 mole；两种判定共用当前图案。
- 出现前手在坑外；随机等待时间避免按固定节奏提前挥手。
- 显示时长可调；200 ms 是候选值，不是已确认的实验参数。
- 初步动作规则：手部检测中心从区域外第一次进入固定击打区域，算一次击打。
- 进入区域那一刻地鼠实际可见，算有效动作；不要求手完全覆盖地鼠。
- 每个地鼠最多命中一次；下一次动作前手须离开击打区域。
- 这是二维区域击打任务，单靠现有图像不能确认实际敲击投影面。

先用较长窗口确认规则和识别可靠，再根据实际“看见到进入区域”的时间选择短窗口。
显示图案和两种判定共用同一套区域，避免识别框随遮挡缩小后改变命中范围。

## 时间与遮挡

若输出延迟近似固定为 L，内部窗口 [0, W] 对应实际投影窗口 [L, W + L]。
实际显示时长仍为 W，未经补偿的内部窗口会提前结束。
例如 W=200 ms、L=40 ms 时，内部窗口为 0～200 ms，实际窗口为 40～240 ms；
发生在 220 ms 的击打可能仍然有效，但内部计时已经结束。

40 ms 投影延迟、45～55 ms 总延迟、150 ms 人的反应时间，目前都不是本任务的实测结果。
开始动作的反应时间与完成击打的时间分开记录，不用通用反应时间直接确定显示时长。

两种方法按动作所在图像帧的时间判定，不按游戏收到结果的时间判定。
现有 capturedAt 是图像转换并复制后的主机时间，不是相机曝光时间；测量时须保留这个限制。
帧处理完成与可见反馈出现也不是同一个时刻。

检测不到地鼠，可能是真消失，也可能被手遮住。第一版先检查部分遮挡下是否仍能识别颜色；
必要时让地鼠外围保留与它同步显示、手不易遮住的颜色区域，两种方法使用相同画面。
中心完全遮挡时可利用同帧同步标记判断显示状态；标记也遮挡或时间边界无法确认时，记录“无法判定”，不能直接算地鼠消失，
也不能随意延长状态保持时间以获得命中。

## 评价与记录

- 玩家表现：实际可见期间的击打成功率，以及看见到开始动作、进入区域的时间。
- 判定表现：对照独立录像标注，统计正确判定、误判、漏判和无法判定。
- 主观体验：是否感觉打中了却没算、反馈是否及时、判定是否容易理解、整体是否容易操作。

相机方法自己的输出不能作为两种方法的正确答案。用包含实际投影面和手的录像进行核对，
时间边界无法分辨的试次保留并报告数量。电脑录屏不能单独证明实际显示时刻。

每次运行先保存一份参数和一份事件 CSV：试次、模式、显示时长、随机种子、
内部出现/消失时刻、图像帧编号/时间、手进入区域时刻、接收/判定时间、结果及不确定原因。
实际投影出现/消失和可见反馈时刻，由图像观测或录像核对填写，并明确来源。
同一批参与者体验两种方法，平衡顺序，避免把练习效果当作方法差异。

两种判定方式的实机比较按次留档，保留参与者代号、判定方式、显示时长、设备/环境条件、
时间数据、判定结果、现场观察及图像/录像证据，供后续比较反应速度和可视化分析。

### 实验记录与反应速度（2026-10-25）

记录对象是参与者使用两种判定方式的实机实验。每次实验保存条件说明，
每次地鼠出现/击打保存一条试次记录；成功、漏判、误判及无法判定的试次均保留。
以下作为后续记录规范；自动成绩记录与汇总等程序完成、实机验证后再实现。

| 比较指标 | 定义与数据来源 |
| --- | --- |
| 人的动作时间 | 从地鼠实际出现到手开始移动、进入击打区域的时间；由实际投影与手的录像标注。出现到进入包含反应与移动过程，不称为纯反应时间。 |
| 系统判定延迟 | 动作帧的主机采样时间到程序作出判定的时间，由程序日志记录；另由录像测量实际手进入到可见反馈出现的延迟。两项分别报告。 |
| 最短稳定通过时长 | 同一参与者在每种方式下按统一成功率标准稳定通过的最短显示时长；同时保存每档全部试次的命中数、总数和 UNJUDGED 数。 |

试次至少关联会话编号、参与者代号、判定方式、体验顺序、试次编号、显示时长、
内部显示提交时刻、动作帧号/主机采样时刻、程序接收/判定时刻、结果和不确定原因。
实际投影出现/消失、手开始移动/进入区域、可见反馈出现的时刻及录像路径，由录像标注补充。
现场文字备注记录光线、设备位置、遮挡和异常，数值明细后续用于生成表格与图表。

时间差必须在同一时钟内计算；主机日志时间不能直接减去独立录像时间，除非已完成时间对齐。
当前 capturedAt 仍是转换复制后的主机时间，现有日志也不等于真实曝光或可见反馈时刻。
相机观测评分已接入代码，完整实验试次汇总尚未实现；以上记录规范不能当成已采集的数据。

### 逐步缩短显示时间的对照方案（2026-10-20）

同一参与者分别体验内部计时和相机观测两种模式，两种模式均逐步缩短地鼠显示时间，
比较每个人在两种模式下能够稳定通过的最短显示时长，作为“最好成绩”的主要定义。
单次偶然命中的最短时长只作补充记录，不作为主要结论。

- 两种模式使用相同的时长档位和缩短规则，例如 `500 → 400 → 300 → 250 → 200 ms`。
  具体档位根据实机试玩确定，正式比较前固定。
- 每档重复多次，按预先确定的成功率标准判断是否通过，并重复确认临界档位。
  初步可试每档 10 次、至少命中 8 次；这些数值是候选方案，尚未定为正式实验参数。
- 两种模式共用设备、标定、图案、手部检测、击打区域、动作规则、随机等待分布和反馈形式，
  练习量、每档试次数、临界档位确认及停止规则保持一致；均安排相同的休息机会。
- 平衡模式体验顺序：部分参与者先内部计时后相机观测，其余反过来，减少练习和疲劳的影响。
- 保留每人、每档的命中数、总试次数及 UNJUDGED 数；UNJUDGED 单独报告，
  不计为命中，也不静默剔除后计算通过率。比较同一参与者两种模式的最短稳定通过时长及差值。

系统给出的成绩属于客观表现指标，公平感和响应感另作主观评价。
成绩提高仍须结合独立录像核对：检查实际有效动作的漏判是否减少，以及误判是否增加，
避免仅凭系统给分更高就认定判定更准确。
首轮结论限定为与当前未经显示延迟补偿的内部计时方案比较，不能直接推广到所有内部计时方案。

## 下一步顺序

1. 在独立的 MoleGame 目录使用已有 C++、OpenCV、pylon、TensorRT 环境。
2. 实机验证相机预览与单手检测；模型静态图片检查不能代替真实手部验证。
3. 加入一个坑和固定图案，验证随机显示与同帧图像中的实际显示状态。
4. 实机检查遮挡与短显示窗口，验证已接入的两种判定是否按共用动作规则运行。
5. 保存事件记录，拍摄实际投影画面；根据试玩选择显示时长，再准备主观评价。

第一版保持紧凑。出现真实需要后再增加模块或实验条件。
